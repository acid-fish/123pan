> 版本：1.3
>
> 更新日期：2026-09-23
>
> 适用分支：`roundSync`

> 状态：实现完成，自动化测试和真实环境验收通过

## 重要说明

- 删除传播保持显式启用，默认不会因为一端文件消失而自动删除另一端文件。
- 云端删除传播到本地时，普通文件进入操作系统回收站，不会回退为永久删除。
- 本地删除传播到云端时，调用 123 云盘回收站接口。
- 持续出现下载链接错误 `24010` 时，本轮剩余下载及两端删除都会被阻止。
- 同一个同步任务内按文件串行处理；大文件内部仍可使用既有 Range 分片下载。

## 1. 实施结论

本次实现为桌面客户端增加了完整的双向同步能力，并补齐了运行可观测性和删除安全保护：

- 根据本地、云端和上次同步快照计算双向变更。
- 支持上传、下载、双向删除、冲突策略和目录创建。
- 上传和下载均提供字节级进度。
- 每次同步显示独立、可移动、非模态的详情窗口。
- 启动最小化时仅隐藏主窗口，同步详情窗口仍会显示。
- 下载链接返回 `24010` 时采用有限退避重试并阻止危险删除。
- 本地删除改为系统回收站操作。
- 删除传播未启用时，明确显示“保留本地文件”或“保留云端文件”，不再误报“已是最新”。

真实环境验收结果：

1. 在云端删除 `123pan - v211.zip` 后执行同步，本地对应文件成功进入 Windows 回收站。
2. 在本地删除 `123.txt` 后执行同步，云端对应文件成功进入云端回收站。
3. 用户确认两条删除传播链路实测成功。

## 3. 配置与数据位置

双向同步任务不存放在项目源码目录中，而是存放在用户配置数据库：

- Windows：`%APPDATA%\123pan-ng\123pan.db`
- Linux/macOS：`~/.config/123pan-ng/123pan.db`

主要数据表：

| 表 | 用途 |
| --- | --- |
| `bi_sync_jobs` | 双向同步任务配置 |
| `bi_sync_state` | 本地与云端上次确认状态 |
| `bi_sync_history` | 每次运行结果 |
| `accounts` | 账号配置 |

关键任务字段：

| 字段 | 语义 |
| --- | --- |
| `local_path` | 本地同步根目录 |
| `remote_dir_id` | 云端同步根目录 ID |
| `interval_seconds` | 定时同步间隔，`0` 表示不定时运行 |
| `enabled` | 任务是否启用 |
| `delete_remote` | 本地删除后是否删除云端项目 |
| `delete_local` | 云端删除后是否处理本地文件 |
| `conflict_policy` | 冲突处理策略 |
| `sync_on_startup` | 登录成功后是否立即同步 |

复制项目源码不会复制这些任务。跨电脑迁移时，应重新创建任务，或在确认账号和机器凭据兼容后单独迁移用户配置。

## 4. 架构设计

### 4.1 模块边界

```text
MainWindow
  ├─ BiSyncManager
  │    └─ BiSyncRunThread
  │         └─ BiSyncService
  │              ├─ SyncService / UploadService
  │              ├─ DownloadService
  │              └─ BiSyncStore
  └─ BiSyncProgressController
       └─ BiSyncProgressWindow
            └─ BiSyncRunPage / BiSyncItemTableModel
```

职责划分：

- `BiSyncService`：扫描、计划、执行和状态更新，不依赖 Qt。
- `BiSyncRunThread`：在工作线程运行服务，将服务事件包装为带 `run_id` 的 Qt 信号。
- `BiSyncManager`：管理任务调度、线程生命周期和启动同步。
- `BiSyncProgressController`：合并高频进度事件并管理详情窗口。
- `BiSyncProgressWindow`：显示任务计划、文件状态和总进度。
- `move_to_system_trash()`：封装 Qt 系统回收站 API，由任务层注入服务层。

### 4.2 事件链路

服务层使用不可变事件对象报告运行状态：

```text
RUN_STARTED
  → PHASE_CHANGED
  → PLAN_READY
  → ITEM_STARTED
  → ITEM_PROGRESS ...
  → ITEM_FINISHED
  → RUN_FINISHED
```

事件中包含：

- 稳定的 `item_id`。
- 操作类型。
- 相对路径、文件名、类型、大小和修改时间。
- 已传输字节数和总字节数。
- 单项状态和错误消息。
- 运行摘要与统计数据。

原有 `_SyncJobSignals` 接口保持不变，避免影响单向同步和已有界面。

## 5. 同步判定模型

同步计划由三份数据共同决定：

1. 当前本地索引。
2. 当前云端索引。
3. `bi_sync_state` 中上次确认快照。

### 5.1 常规文件判定

| 本地状态 | 云端状态 | 快照 | 结果 |
| --- | --- | --- | --- |
| 新增 | 不存在 | 无 | 上传 |
| 不存在 | 新增 | 无 | 下载 |
| 修改 | 未修改 | 有 | 上传 |
| 未修改 | 修改 | 有 | 下载 |
| 修改 | 修改 | 有 | 按冲突策略处理 |
| 未修改 | 未修改 | 有 | 无操作 |

首次接触两侧同名文件时：

- 大小相同：采纳为共同基线，不重复传输。
- 大小不同：按冲突策略处理。

### 5.2 删除传播判定

| 观察结果 | 开关 | 行为 |
| --- | --- | --- |
| 本地文件消失，云端未变化 | `delete_remote=1` | 删除云端项目 |
| 本地文件消失，云端未变化 | `delete_remote=0` | 保留云端文件并显示阻止原因 |
| 云端文件消失，本地未变化 | `delete_local=1` | 本地文件移入系统回收站 |
| 云端文件消失，本地未变化 | `delete_local=0` | 保留本地文件并显示阻止原因 |
| 本地消失，但云端已修改 | 任意 | 下载云端版本，不执行删除 |
| 云端消失，但本地已修改 | 任意 | 重新上传本地版本，不执行删除 |

删除传播关闭时，会生成 `KEEP_REMOTE` 或 `KEEP_LOCAL` 计划项，状态显示为“已阻止”，统计计入“保留”。这避免了检测到单边删除却显示“已是最新”的误导。

### 5.3 冲突策略

- `keep_both`：主路径保留本地版本，云端版本下载为带时间戳的冲突副本；副本下次作为新文件上传。
- `local_wins`：本地版本覆盖云端版本。
- `remote_wins`：云端版本覆盖本地版本。

文件与目录同名属于类型冲突。系统记录失败并跳过，不破坏任一侧数据。

## 6. 执行顺序与并发

单个任务按以下顺序执行：

1. 扫描本地目录。
2. 获取云端完整索引。
3. 计算并发布同步计划。
4. 创建云端目录。
5. 串行上传文件。
6. 创建本地目录。
7. 串行下载文件。
8. 下载冲突副本。
9. 删除云端项目。
10. 将本地文件移入系统回收站，并清理空目录。
11. 报告类型冲突和被配置阻止的删除。
12. 写入历史记录并刷新界面。

并发语义：

- 同一任务内的不同文件串行处理。
- 上传调用保持 `num_threads=1`。
- 大于阈值且服务器支持 Range 的单个下载文件，可使用既有分片线程。
- 多个启用任务仍可分别启动工作线程并发运行。

因此，将文件改为串行不能解决 `24010`；文件级串行在问题发生前已经存在。

## 7. 下载链接错误 24010

错误发生于请求下载链接阶段，早于 HTTP 文件传输和 Range 分片：

```text
/a/api/file/download_info
  → code=24010
  → 尚未开始下载文件内容
```

处理策略：

1. 首次失败后等待 5 秒。
2. 第二次失败后等待 15 秒。
3. 第三次仍返回 `24010` 时，将当前文件标记失败。
4. 剩余下载和冲突副本标记为已阻止。
5. 跳过本轮云端删除和本地删除。
6. 保留完整服务端错误码和消息。
7. 退避期间每 100 ms 检查取消状态。

该策略可以吸收短暂服务端状态，但不能伪装真实配额问题。持续失败时优先保护数据一致性。

## 8. 本地回收站安全设计

本地文件删除使用 `QFile.moveToTrash()`：

- Windows 使用系统回收站。
- macOS 使用系统废纸篓。
- Linux 使用 FreeDesktop Trash 规范。
- 符号链接移动链接本身，不处理链接目标。

失败语义：

- 不支持回收站、权限不足或文件系统异常时，本项同步失败。
- 不调用 `os.remove()` 作为降级方案。
- 文件保留原位。
- `bi_sync_state` 快照继续保留，供下次同步重试。

目录处理仍使用 `os.rmdir()`，且只允许删除空目录。这样可保留原有原子安全检查，避免目录检查后新增的未知文件被整体移动或删除。

## 9. 上传正确性保护

上传路径包含以下保护：

- 使用统一覆盖语义 `dup_choice=2`，减少同名文件竞态。
- 传入 `refresh_session`，令牌过期时可自动重新登录。
- 上传完成后重新查询云端目录，确认文件真实注册成功。
- 服务端未确认文件时计失败，不写入成功快照。
- 秒传或无正常字节回调的成功路径主动补发 100% 进度。

这些保护避免“接口看似成功但云端未出现文件”导致下一轮误判为云端删除。

### 9.1 现行上传协议

当前上传链路已适配服务端的新协议：

- 分片大小优先采用 `upload_request` 返回的 `SliceSize`，缺省为 16 MiB。
- 单分片文件通过 `/b/api/file/s3_upload_object/auth` 获取预签名地址。
- 多分片文件通过 `/b/api/file/s3_repare_upload_parts_batch` 获取分片地址。
- 上传完成调用 `/b/api/file/upload_complete/v2`，提交存储节点、桶、文件 ID、大小、对象键和上传 ID。
- 不再依赖旧的 `s3_complete_multipart_upload` 与旧版 `upload_complete` 完成链路。
- 完成响应缺少 `file_info` 时执行有限重试，随后再通过目录列表独立确认。
- 续传记录的历史分片大小与当前服务端分片大小不一致时，放弃旧会话并重新上传。

该协议同时服务普通上传界面和双向同步上传路径。

## 10. 同步详情窗口

窗口特性：

- 独立顶层窗口，无父窗口依赖。
- 非模态，不阻塞主界面操作。
- 不设置置顶标志。
- 首次显示时位于当前屏幕中央，用户移动后不自动复位。
- 同步完成后保持显示，直到用户关闭。
- 用户在运行中关闭时只隐藏窗口，不取消同步。
- 启动最小化时主窗口保持隐藏，详情窗口仍可见。

表格字段：

- 操作。
- 名称。
- 类型。
- 大小。
- 修改日期。
- 单文件进度。
- 状态和失败原因。

总进度采用工作量加权：

- 传输文件权重为 `max(file_size, 1)`。
- 目录、删除和保留操作权重为 `1`。
- 同时显示已处理项数以及已传输/总字节数。

高频字节进度在控制器中按 100 ms 合并更新。每个任务复用自己的页签，定时运行不会无限新增页面。

## 13. 发布与回滚

### 13.1 发布前检查

- 不提交 `%APPDATA%\123pan-ng\123pan.db`。
- 不提交 `.keyfile`、账号凭据或日志。
- 不提交截图、pytest/mypy 缓存或 `__pycache__`。
- 确认新增源码和测试文件均已纳入 Git。
- 检查 `git diff --check`。
- 在提交前复核 `git status --short`。

### 13.2 配置兼容

v1.3 增量没有新增数据库迁移。双向同步基础表仍由既有的
`CREATE TABLE IF NOT EXISTS` 初始化逻辑维护，现有任务继续使用原字段：

- 已有删除开关值保持不变。
- 新建任务仍默认关闭删除传播。
- 每次运行前从数据库重新读取任务配置，无需重建任务。

### 13.3 回滚原则

若需要回滚界面功能，可移除详情控制器和新增事件转发，原有同步信号仍可继续工作。

若需要回滚删除传播设置，应通过任务编辑界面关闭对应开关，不应直接删除同步快照。保留快照可以防止下一轮将旧文件误判为首次出现。
